# Primary sources and novelty boundaries

Inspection date: 2026-10-05. Paper versions below are preprints; no acceptance or independent replication is asserted. Source summaries are intentionally bounded to the inspected interfaces and evaluations.

| Source | What was inspected / established | Consequence for this candidate |
|---|---|---|
| [AWS: Making retries safe with idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) | Identical parameters need not mean identical intent; caller-provided request identifiers distinguish operations and support safe retries. | Neither that distinction nor idempotency keys are novel. The proposed experiment concerns how a conversational caller chooses an identity. |
| [Cordon, v1](https://arxiv.org/html/2606.17573v1) | Sections 3–5 explicitly separate same-task retries from new task scopes and attach task identifiers to runtime calls. Section 6 evaluates containment, recovery and benign task correctness. | Closest systems precedent. The inspected evaluation does not establish performance on the proposed paired dialogue test. This is a possible measurement extension, not proof that Cordon cannot handle it. Its implementation/task-boundary adapter still needs comparison if available. |
| [Verified Tool Calls Improve LLM Agent Reliability Under Non-Atomic Failures, v1](https://arxiv.org/html/2608.02645v1) | Verifies uncertain outcomes and uses idempotency across attempts; evaluation includes customer activation and invoice recording. | Generic verification-before-retry is already covered. We need legitimate extra operations and false-suppression measurement, not another wrapper demonstration. No replication performed. |
| [IdempotencyBench at pinned revision](https://github.com/gssanjana4/idempotencybench/tree/1b9b30fd37f983d6e2eb0ebf535bfcb1086fb311) | `src/world.py` scopes semantic effects and runtime receipts with `task_id`; `src/model_agent.py` passes a fixed task ID to `world.call`. `src/tasks.py` ambiguity variants still describe one intended effect. The tree contains model-result artifacts; those results were not audited here. | The inspected harness supplies task boundaries to the world/scorer. It does not by itself test inferring a fresh operation boundary across user turns. This is not a claim that its model prompt exposes the ID, or that its benchmark has no value. |
| [latch at pinned revision](https://github.com/sangaraju1988/latch/tree/e56c857685d8a4b5b281f187253026eabf194445) | `src/latch/core.py` requires a caller-provided `idempotency_key`, stores successful results and serializes same-key execution. | Useful runtime precedent. Correctly supplying a logical operation key is the caller's contract; its absence of dialogue interpretation is not a defect. |
| [Irrevon at pinned revision](https://github.com/PranavMishra28/irrevon/tree/9a933b080d8dddd9ddd4faf2ca71e3f7d54b2a2a) | Follow-up inspection covers identity code, runner, public fixtures and arm registry: stable IDs are supplied externally; four public development variants are same-intent; the proposed model-assisted arm is not implemented. See [exact evidence](PRIOR_ART_CHECK.md). | Same/new-intent design and two-sided metrics are prior art. Public fixture scope differs from this dialogue pilot, but sparse public fixtures do not prove novelty or reveal private holdouts. |
| [ACRFence v1](https://arxiv.org/html/2603.20625v1) | Proposes a lightweight model for semantic replay-versus-fork checks; the proposed analyzer is not evaluated in the inspected paper. | Small-model semantic operation matching is also prior design. This pilot measures a possible dialogue-boundary extension, not a new matching method. |
| [Mind the Gap / TOCTOU-Bench](https://arxiv.org/abs/2508.17155), [STALE](https://arxiv.org/abs/2605.06527) | Primary paper records on state changes between checking and use / invalidated memory. | Generic stale-state evaluation has direct predecessors; it is not the selected standalone direction. |
| [Remember, Verify, or Ask?](https://arxiv.org/abs/2608.19564), [Learning to Ask](https://arxiv.org/abs/2409.00557) | Primary paper records on verification and clarification decisions. | Asking when uncertain is an existing approach and a required comparator, not a novelty claim. |

## Reuse plan and obligations

First compare contracts; do not fork simply to create a dependency. If the pilot survives, adapt IdempotencyBench's failure-injection/effect accounting or add a separate operation-boundary suite while preserving its existing task semantics. Compare a mature idempotency runtime rather than advertising our toy ledger as production software. Review exact licenses for all files used, retain notices, record modifications and commit pins, and cite the authors. IdempotencyBench's README distinguishes code and data licensing; a code license must not be assumed to cover all task/transcript material. The current independently written simulator uses no Kev or Laya code and does not imply that earlier repository work lacked such influences.

## Outstanding novelty checks

Search multi-turn tool-use benchmarks for cross-turn repeats, duplicate requests, correction/cancellation and user-intent segmentation. Inspect Irrevon's actual fixtures and Cordon's task-scope construction, not merely their terminology. These precedents already prevent claiming novelty for the two-sided metrics or the scope distinction. Determine whether their materials include natural-language boundary inference under identical payloads. If the same question and evaluation already exist, reproduce or extend that work instead of naming a new benchmark. A search failing to find an exact match is not evidence of priority.
