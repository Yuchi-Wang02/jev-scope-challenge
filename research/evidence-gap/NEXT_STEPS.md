# Next steps after the development diagnostic

This is a proposed plan, not an executed follow-up study. The current frozen
results are complete and must not be overwritten. Reserved model scores remain
absent. Independent human review is deferred while automated preparation is complete.

## 1. Review meanings before measuring held-out performance

Use the six-item starter to test reviewer understanding, then arrange independent
review of the 288 candidates and policy wording. Record who reviewed what and
whether they saw results/program labels. Resolve conflicts and ambiguities with
recorded reasons. Do not equate agreement with program gold to independent truth,
or delete cases because models perform poorly. Any change receives a new data
version, parent-grouped split and protocol. Public reserved text is not secret.

## 2. Formulate one falsifiable hypothesis on development

Candidate: **a decision pipeline that explicitly checks whether required target
facts are determined can reduce unsupported commitments without increasing
false abstention on logically nondecisive deletions.** This describes a hypothesis,
not an already working or novel method. The present null-subtraction results
show why total accuracy alone cannot be its success criterion.

Predefine paired deletion correctness, uncertainty false commitments, supported
view false abstentions, complete-parent correctness and full computation costs.
Report family/order breakdowns and correction/regression counts. Statistical
resampling should use parent groups, not each order/view as independent examples.
Choose sample-size targets from an explicit desired precision/power analysis
before adding confirmation data; 12 development parents cannot provide it.

## 3. Build an ablation ladder, not one privileged helper

|Proposed path|What it tests|Control or limit|
|---|---|---|
|Raw three-way readout|Current failure anchor|Keep fixed prompt/order source|
|Two-order or fixed-budget reasoning|Ordinary extra compute|Charge all calls/tokens|
|Max-score or margin abstention|Generic uncertainty rule|Fit only on reviewed released calibration; scores are not correctness probabilities|
|Explicit fact-availability/conflict guard|Mechanism-specific evidence check|Count extraction cost and false abstentions; no gold metadata|
|Known-grammar parser + policy solver|Code reference when schema is known|Construction-specific, not general NLP capability|
|Instruction-tuned native model|Whether Base/native causes the weakness|Pin weights, prompt, thinking mode and budget; no unapproved download|
|Additional decision endpoints, including Jev|Whether this boundary transfers|Separate protocol and budget before paid calls; Kev is not Jev|

A guard built from our known grammar receives a stronger program prior than a
general model. It cannot be described as a pure inference fix without reporting
that knowledge. Give decision-model baselines the corresponding helper, or label
the experiment as a pipeline comparison. Separately measure extraction errors
and policy execution errors. An oracle fact mask is an upper reference, never
an implementable deployment result. If several fixes fail, preserve that outcome.

## 4. Release reviewed calibration, then an untouched test

Write a separately versioned protocol after review: candidate methods, threshold
selection, prompts/representations, primary endpoint, model revisions, run/cost
limits, failure/retry accounting and stop gates. Open calibration only for its
stated fitting purpose. Freeze selected settings and evaluate test once. The
composed mechanism is reserved as a transfer check, alongside the grouped styles;
that mix must be disclosed or redesigned into a separate factorial study.

## 5. Make the public artifact useful to others

The current repository already contains all inputs, forward records, counts,
code, fixed protocol, figure and an offline explorer. An accurate public line is:
**“We deleted the deciding evidence. The model often kept a decision. Here's the
paired control and every result.”** Link to development status and review gaps.
The more defensible novelty target is a reusable evidence-sufficiency evaluation
and a tested pipeline improvement across several mechanisms/sources—not standard
softmax, logit subtraction, order averaging or the known pointer architecture.

After independent review, consider a versioned Hugging Face dataset and a saved-
result Space with a clear data card. No HF publication, hosted inference, trained
checkpoint or paper submission has occurred in this stage. External contributors
could add new independently labeled mechanisms and run frozen baselines; their
data/model licenses and provenance must be preserved. No outreach was sent.
